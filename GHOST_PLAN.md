# План плагина `!ghost` (CS2, Metamod:Source 2)

Цель: мёртвый игрок в режиме «Маньяк» может бегать по карте призраком.
Он **никак** не влияет на игру. Его нельзя ударить или подстрелить, он не загораживает
союзников, его не видно и не слышно, и он ничего не активирует.

---

## 1. Ключевые решения

Это то, что я поменял или добавил к исходному черновику.

| Задача | Основной способ | Подстраховка |
|---|---|---|
| Не получать урон и не перехватывать нож и пули | Слои взаимодействия: `m_collisionAttribute.m_nInteractsAs = 0` (пешка «никем не является» для трейсов), `m_nInteractsWith = только мир` (ходит по полу), а также все хитгруппы отключены в `CHitboxComponent::m_bvDisabledHitGroups` | Хук трейс-фильтра (`ShouldHitEntity`), который игнорирует пешку призрака, и `m_takedamage = DAMAGE_NO` |
| Невидимость | **`CheckTransmit`**: пешку призрака (и её оружие, перчатки, wearables) не передаём никому, кроме самого призрака. Нет модели, тени, радара, частиц, и клиент даже не знает, где призрак | `EF_NODRAW \| EF_NOSHADOW`, `kRenderNone`, `m_bSpotted = false` |
| Тишина | `CheckTransmit` уже убирает большую часть. Остальное режет хук `PostEventAbstract` / `EmitSound` по entity-index пешки | Нулевой `m_flVelocityModifier` для звуков не нужен, только хук |
| Нет E и атак | `ProcessUsercmds`: вырезаем `IN_USE, IN_ATTACK, IN_ATTACK2, IN_RELOAD, IN_LOOKATWEAPON`, плюс блок команд `drop`, `buy*`, `use`, `lastinv` и подбор (`CanAcquire`/`Weapon_CanUse` → false) | Удаление всего оружия раз в секунду |
| Триггеры карты | **Новое:** хук `StartTouch`/`Touch` у `trigger_*`: для пешки призрака возвращаем без действия (`trigger_once`, телепорты, `trigger_hurt`, кнопки по касанию) | Флаг `FL_NOTARGET` (боты и NPC не целятся) |
| Конец раунда | **Новое:** призраки не «ломают» подсчёт: когда у команды не осталось живых не-призраков, плагин сначала тихо убирает всех её призраков, и движок завершает раунд штатно | Своя проверка в `player_death`/таймере |
| Статистика | Тихий уход из режима: `player_death` для призрака блокируется, `m_iDeaths`/счёт восстанавливаются, в килфиде пусто | — |

Почему слои, а не только `SOLID_NONE`: в Source 2 нож и пули идут трейсом по
**хитбоксам** с маской `MASK_SHOT`/`CONTENTS_HITBOX`, а не по коллизии. `SOLID_NONE`
убирает физическое столкновение, но хитбоксы остаются. Поэтому важнее обнулить
`m_nInteractsAs` и отключить хитгруппы. Именно это проверяет этап 0.

## 2. Структура

```
ghost/
├── ghost.cpp          // ISmmPlugin: Load/Unload, хуки, команды
├── ghost_state.h      // struct GhostState { bool active; float cooldownUntil; int savedDeaths; ... } g_Ghost[64]
├── ghost_apply.cpp    // Apply/Reapply/Remove: коллизия, видимость, оружие
├── ghost_hooks.cpp    // ProcessUsercmds, CheckTransmit, PostEventAbstract, TraceFilter, Touch
├── ghost_round.cpp    // подсчёт живых, тихое удаление призраков
├── gamedata.json      // сигнатуры и оффсеты (не хардкодить: ломаются после апдейтов CS2)
└── ghost.cfg          // ghost_enabled, ghost_cooldown, ghost_log
```

Состояние на слот (а не просто `bool ghost[64]`): `active`, `cooldownUntil`,
`savedDeaths/score`, `serial` (защита от переиспользования слота после дисконнекта).

## 3. Команды

- `!ghost`: проверки → вход в режим.
  1. игрок мёртв и в команде T/CT (не спектатор);
  2. включён режим «Маньяк»;
  3. раунд идёт (не warmup, не freeze, не после `round_end`);
  4. кулдаун прошёл;
  5. в команде ещё есть живые не-призраки (иначе раунд всё равно кончается).
- `!unghost`: тихий выход, игрок снова мёртв (без записи в килфид и статистику).
- `css_ghost_off` / `ghost_enabled 0` (админ): мгновенно выводит всех и отключает плагин.

## 4. Этапы

### Этап 0. Прототип неосязаемости (делаем первым, остальное зависит от него)
Консольная команда, которая делает живого тестового игрока «призраком» без всего остального:
- `m_nInteractsAs = 0`, `m_nInteractsWith = CONTENTS_SOLID/мир`, `m_nInteractsExclude = игроки`;
- `m_CollisionGroup = COLLISION_GROUP_DEBRIS` (или аналог, который не блокирует игроков);
- хитгруппы отключены в `m_bvDisabledHitGroups`;
- `CollisionRulesChanged()` + `NetworkStateChanged` для изменённых полей. ⚠️ Нужны оффсеты.

Тест двумя клиентами:
- нож ЛКМ и ПКМ спереди, сзади, в прыжке, в присяде;
- нож и пули по цели, стоящей **за** призраком: удар должен пройти насквозь;
- HE/молотов/флеш рядом: ни урона, ни блока осколков;
- призрак ходит, прыгает, приседает, по лестницам, не проваливается сквозь пол и пропы.

**Готово**, когда 0 попаданий из 50 ударов в каждой позиции и цель за призраком получает урон.
Если нет → **0б**.

### Этап 0б. Фильтр трейсов
Хук `CTraceFilter::ShouldHitEntity` (или функции трейса оружия): если сущность — пешка
призрака или её дочерняя сущность, вернуть `false`. Удар проходит насквозь, перехвата нет.
⚠️ Нужна сигнатура под твой билд.

### Этап 1. Вход в режим
1. `Respawn()` в точке смерти (или на спавне команды, это настройка).
2. Сразу после спавна (в следующем кадре, т.к. игра выдаёт оружие в `PostSpawn`):
   снять всё оружие, `m_takedamage = DAMAGE_NO`, `FL_NOTARGET`, применить этап 0.
3. Подавить для других плагинов `player_spawn` и аналогичные хуки, чтобы это не считалось новой жизнью
   (маньяк не должен выбрать призрака целью, счётчики живых не должны меняться).
4. Сохранить `m_iDeaths`/`m_iScore`, чтобы восстановить при выходе.

### Этап 2. Невидимость
- Основное: `CheckTransmit` убирает пешку и все её дочерние сущности (оружие, перчатки, wearables, частицы)
  из пакетов всех игроков, кроме самого призрака.
  Контроллер **не** скрываем, иначе ломается таблица счёта.
- Плюс: `EF_NODRAW | EF_NOSHADOW`, `m_nRenderMode = kRenderNone`, alpha 0 (на случай наблюдателей и демо).
- `m_bSpotted`/`m_bSpottedByMask` = 0 каждые 0.25 с: не всплывает на радаре.
- В таблице счёта призрак остаётся «мёртвым» (череп). Проверить, не показывает ли
  scoreboard его живым; если показывает, это уже поведение `m_bPawnIsAlive` на контроллере, и тут
  решаем отдельно.
- Мёртвые наблюдатели не могут переключиться на призрака (фильтр `spec_next`/observer target).

### Этап 3. Блокировка ввода и взаимодействия
- `ProcessUsercmds`: убрать кнопки из `buttons`, `buttons_changed`, `buttons_scroll`
  (в CS2 кнопки дублируются в нескольких полях protobuf-команды, чистить все). ⚠️
- Команды: `drop`, `buy`, `buymenu`, `autobuy`, `rebuy`, `use`, `+lookatweapon`, `player_ping` → блок.
- Подбор оружия по касанию: хук `CanAcquire`/`Weapon_CanUse` → false.
- Двери, кнопки, `func_button`, `prop_door_rotating`: E вырезан, а касание — этап 4.
- Пинг-метки и граффити (`player_ping`, спреи): блок, иначе это канал общения с живыми.

### Этап 4. Триггеры и физика
- Хук `Touch/StartTouch/EndTouch` для `trigger_*`, `func_button` (с флагом «touch»), `func_door`:
  пешка призрака игнорируется.
- Физпропы: призрак их не толкает (`m_nInteractsWith` без `CONTENTS_PHYSICS`/debris). Проверить,
  что он не ходит «по воздуху» над ними и не проваливается.
- Урон от падения и `trigger_hurt`: уже отрезаны `DAMAGE_NO` + блоком триггеров.

### Этап 5. Звук и чат
- `CheckTransmit` убирает большую часть звуков, привязанных к сущности.
- Хук `PostEventAbstract` (`CMsgSosStartSoundEvent` / `EmitSound`): если источник — пешка призрака,
  убираем из списка получателей всех, кроме самого призрака. Шаги, прыжки, приземление, лестницы, вода.
  ⚠️ Проверить на сервере логом, какие события и с каким source-entity летят.
- Голос и чат: призрак — для правил чата **мёртвый**. Живые его не слышат и не видят его сообщения.

### Этап 6. Раунд и режим «Маньяк»
- Правило: призрак никогда не должен быть последним «живым» своей команды.
- На `player_death` (и в таймере): если у команды 0 живых не-призраков, то сначала тихо убираем
  всех её призраков (смерть без события и статистики), после чего движок сам завершает раунд.
- Если «Маньяк» завершает раунд своей логикой (подсчёт живых в плагине/скрипте), то ему нужен
  флаг `IsGhost(slot)` или он должен перестать считать призраков. ⚠️ **Нужен твой ответ.**
- Совместимость с NoBlock и другими плагинами коллизии: ghost переприменяет свои
  настройки последним (в таймере и после `player_spawn` других плагинов).

### Этап 7. Устойчивость
- Таймер 1 с: переприменить коллизию, рендер, `DAMAGE_NO`, отсутствие оружия.
- Полный сброс (`Remove`) при: `player_death` (если всё-таки погиб), `round_start`, `round_end`,
  `player_disconnect`, `player_team`, смене карты (`LevelInit`/`LevelShutdown`), выгрузке плагина.
- Проверка `serial` контроллера, чтобы новый игрок на старом слоте не стал призраком.
- Все указатели на пешку брать заново через handle, не кэшировать.

### Этап 8. Тесты (2–3 клиента + бот)
| Что | Ожидание |
|---|---|
| Нож спереди, сзади, ЛКМ, ПКМ | 0 попаданий |
| Нож и пули по цели за призраком | цель получает урон |
| Гранаты, молотов, флеш | ни урона, ни ослепления, ни блока |
| Союзник проходит сквозь призрака | без застревания, `+use` и прицел на него не реагируют |
| E на дверях, кнопках, оружии; триггеры карты | ничего не происходит |
| Шаги, прыжки, лестница, вода, на слух | тишина |
| Тень, радар, таблица, наблюдатели, демо (`tv_record`) | призрака нет |
| Последний живой умирает при призраках | раунд заканчивается сразу |
| Выход, перезаход, смена команды, смена карты, выгрузка плагина | нет «зависших» призраков, нет крашей |
| 5+ призраков сразу | нет просадок тик-рейта |
| Бот | не стреляет в призрака |

### Этап 9. Выкладка
1. Тестовый сервер, логирование входа и выхода (SteamID, время, причина).
2. Боевой сервер с `ghost_enabled 0` по умолчанию на первые дни, включается вручную.
3. Аварийная команда `css_ghost_off`.
4. После каждого обновления CS2 проверять сигнатуры в `gamedata.json` (при ошибке плагин сам
   отключается, а не крашит сервер).

---

## 5. Главные риски
1. **Нож и пули по хитбоксам.** Решается слоями и хитгруппами на этапе 0, подстраховка — фильтр трейсов в 0б.
2. **Раунд не заканчивается.** Решается тихим удалением призраков (этап 6).
3. **Игра сбрасывает флаги** после респавна, смены оружия, NoBlock. Решается таймером и порядком применения.
4. **Триггеры карты** (`trigger_once`, телепорты) активируются призраком. Этап 4.
5. **Обновления CS2** ломают сигнатуры. Решается `gamedata.json` и безопасным отключением.
6. **Утечка информации** через пинги, чат, голос, наблюдение. Этапы 3 и 5.
